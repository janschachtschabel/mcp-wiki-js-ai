## 1. Executive Summary

Der Server ist sauber strukturiert, klein (~6.600 LOC) und hat einen durchdachten OAuth-Kern
(PKCE, gehashte Tokens, AES-GCM-verschlüsselte Wiki-JWTs, Refresh-Rotation mit Reuse-Erkennung,
CSRF-Origin-Check). **Er ist aber in der Standard-Konfiguration (Compose/Helm mit OAuth) nicht
produktionsreif**, weil der Legacy-Pfad offen bleibt:

1. **Unauthentifizierte SSRF mit Antwort-Rückgabe** (F-01): Jeder kann mit einem beliebigen
   Bearer-Header + `X-Wikijs-Url` (oder `?token=x&url=…`) den Server interne Adressen abrufen
   lassen und bekommt den Inhalt zurück (`wiki_asset_download`).
2. **Routing-Bypass auf den Service-Token** (F-02): Ein leerer `X-Wikijs-Token`-Header schaltet
   OAuth ab und nutzt `WIKIJS_TOKEN`, falls gesetzt — genau der Fall, den `routing.ts` verhindern soll.
3. **Stiller Datenverlust** (F-03): `wiki_page_update` löscht Seiten-CSS/-JS, wenn der Nutzer
   `write:styles`/`write:scripts` hat (typisch: Admins).

**Wichtigste Einzelmaßnahme:** Bei aktivem OAuth den Legacy-Pfad (BYOK-Header/Query, `X-Wikijs-Url`)
standardmäßig abschalten und die Upstream-URL ausschließlich aus `WIKIJS_URL` nehmen.

## 5. Top-Befunde

```
[🔴 CRITICAL] Sicherheit — F-01 Unauthentifizierte SSRF mit Antwort-Rückgabe
  File:     lib/oauth/routing.ts / lib/context.ts / app/[transport]/route.ts / lib/tools/assets.ts / lib/wikijs/client.ts
  Lines:    routing.ts 20–21; context.ts 176–183; route.ts 81–108; assets.ts 51–91; client.ts 200–203, 227–248
  Problem:  Bei aktivem OAuth schickt jeder Request mit beliebigem Bearer (≠ mcp_at_) oder X-Wikijs-Token
            an den UNauthentifizierten Legacy-Handler. Dort wird die Upstream-URL aus X-Wikijs-Url bzw.
            ?url= übernommen — ohne Allowlist. wiki_asset_download (Kategorie read, Preset "full")
            macht ein GET auf <url>/<path> und gibt Text/JSON/Bilder vollständig zurück; GraphQL-Fehler
            geben zusätzlich die ersten 200 Bytes jeder Nicht-JSON-Antwort zurück.
  Why:      Der Server wird zum offenen Proxy ins interne Netz (Docker-Netz, K8s-Cluster, Cloud-Metadata
            169.254.169.254, Postgres-Port-Probing, interne Admin-UIs).

            Compose- und Helm-Konfiguration.
  Beleg:    PoC (offline): Bearer "junk" + X-Wikijs-Url http://169.254.169.254/… → shouldUseOAuth=false,
            ctx.baseUrl=http://169.254.169.254/…, wiki_asset_download=allow.

            X-Wikijs-Url/?url= nur akzeptieren, wenn sie in einer Allowlist (WIKIJS_ALLOWED_URLS) steht;
            "First bytes" aus Fehlermeldungen entfernen.
  Example:  if (oauthEnabled() && process.env.WIKIJS_ALLOW_LEGACY !== 'true') return mcpWithOauth(request);
```

## 6. Alle Befunde (zusätzlich zu den Top-Befunden)

### Sicherheit
- 🟢 **F-11** `wiki_graphql` umgeht die Tag-Sperre und die Mutation-Erkennung — `lib/tools/system.ts` 163–176.
  Raw-Queries laufen ohne Tag-Filter. Die Regex `/(^|[\s{(])mutation\b/` erkennt `,mutation{…}` nicht
  (Kommas sind in GraphQL bedeutungslos). Da der Agent `confirm:true` selbst setzen kann, ist das
  Agenten-Schutz, keine Sicherheitsgrenze. Fix: Tag-Sperre-Grenze in der Doku nennen, Regex durch
  Parsen (`graphql`-Lexer) oder `/\bmutation\b/` nach Entfernen von Kommentaren ersetzen.
- 🟢 **F-12** Inhalt des Fehlertexts kommt aus der URL — `app/oauth/authorize/page.tsx` 90, 101–105;
  `app/me/page.tsx` 44–56. `login_error` wird aus der Query gerendert (React escaped, also kein XSS),
  erlaubt aber gefälschte Hinweistexte auf der echten Domain. Fix: Fehlercodes statt Freitext.
- 🟢 **F-14** Issuer/Basis-URL aus Host-Headern, wenn `PUBLIC_BASE_URL` fehlt — `lib/oauth/metadata.ts` 11–15,
  `app/me/page.tsx` 15–21. In Compose/Helm gesetzt, daher nur bei Fehlkonfiguration relevant.
  Fix: Bei aktivem OAuth `PUBLIC_BASE_URL` erzwingen (Start abbrechen).
- 🟢 **F-15** 2FA-Continuation-Token in der URL — `app/oauth/authorize/decision/route.ts` 92.
  Verschlüsselt, aber landet in Browser-Historie/Proxy-Logs. Fix: als kurzlebiges HttpOnly-Cookie.

### Korrektheit
- 🟡 **F-16** Locale-Default `en` — `lib/tools/pages/shared.ts` 36, `read.ts` 47, `write.ts` 133ff.
  Nach `bootstrap.mjs --locale=de` liegen Seiten unter `de`; Pfad-Lookups ohne Locale schlagen fehl.
  Fix: Default aus `WIKIJS_DEFAULT_LOCALE` bzw. Wiki-Config lesen.
- 🟢 **F-17** `wiki_pages_delete_tree` löscht über alle Locales — `lib/tools/pages/delete.ts` 84–85.
  `LIST_ALL_PATHS` ohne Locale; gleiche Pfade in anderen Sprachen werden mitgelöscht.
  Needs verification, ob gewollt; sonst Parameter `locale` ergänzen.

### API / Dokumentation
- 🟢 **F-13** `/.well-known/mcp.json` beschreibt nur Legacy-Auth — `app/.well-known/mcp.json/route.ts` 21–25.
  Fix: OAuth-Discovery (`/.well-known/oauth-protected-resource`) referenzieren.
- 🟢 **F-18** `engines.node >=18.18` — `package.json` 39–41. OAuth braucht Node ≥ 22.5. Fix: `>=22.5`.

### Tests
- 🟡 **F-19** Fehlende Regressionstests für F-01/F-02/F-03/F-05 — `scripts/test-routing.ts`,
  `scripts/test-context.ts`. Fix: Testfälle für leeren Header, URL-Override bei OAuth an,
  Update ohne scriptCss, leeres `find`.

### Deployment
- 🟢 **F-20** Session-Secret als Klartext im Values-File — `deploy/helm/wikijs-mcp/values.yaml` (oauth.sessionSecret),
  `templates/secret-env.yaml`. Fix: `existingSecret`-Option, damit das Secret nicht in Git/Helm-Release-Historie landet.
